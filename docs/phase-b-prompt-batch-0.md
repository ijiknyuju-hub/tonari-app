# Phase B バッチ0 — 入り口皿17皿の紹介文生成（場面型）

あなたのタスクは、料理17皿それぞれに2行の紹介文を書くことです。**紹介文だけ**を書きます。
特徴量（食材・調味料・調理法）は既に確定済みで、あなたが変更・再生成することは絶対にありません。

## 入力

このリポジトリの `data/phase-b/batch-0.json` を読んでください。17皿それぞれに
name / box / tier / seasonings / ingredients / methods / primary_method / steps が入っています。
これは**読むための材料**です。あなたはこの特徴量を出力に含めません。

## 出力

`data/phase-b/intros-batch-0.json` に、以下の形式で17件の配列を書き出してください。**これ以外のフィールドを足さない**:

```json
[
  {"name": "唐揚げ", "intro_line1": "...", "intro_line2": "..."},
  ...
]
```

17皿すべてを、`batch-0.json` と同じ順序・同じ name 表記で出力すること。1皿も落とさない、増やさない。

## 文体（このバッチは「場面型」）

これは入り口皿——料理をこれから始める人が最初に作る主菜です。**1行目は「その皿が食卓に登場する場面」**を書き、
**2行目は「作る側の現実（着手の心理的障壁を下げる一文）」**を書きます。

## 拘束ルール（7条）

1. 各行は15〜25字、句点「。」で締める。感嘆符は禁止。
2. 宣伝語（絶品・人気・やみつき・たまらない・ご飯が進む 等）は禁止。どの皿にも貼れる文は失格。
3. 各皿の紹介文には、その皿に固有の食材・技法・数字のいずれかを最低1つ入れる。
4. 1行目＝その皿が登場する場面。2行目＝着手の心理的障壁を下げる一文。皿の労力に応じて、時短訴求（軽い皿）〜工程分解の安心（重い皿）から強度を選ぶ。
5. 食材・調味料名は `batch-0.json` に出てくる語の範囲で書く。外の語（「チキン」等のカタカナ言い換え含む）を持ち込まない。
6. 同じ言い回しを複数の皿で使い回さない。皿ごとに違う切り口で書く。
7. 工程数を文頭に置いた「N工程なら／N工程でも／N工程だから」は禁止。数字を使う場合は、時間・火加減・調味料数など、着手を具体的に助ける情報として使う。

## 模範例（場面型・逐語で従うこと）

**肉じゃが**
> 甘辛い匂いが台所に広がる、はじめての煮物の定番。
> 材料を切って煮るだけ、味付けは調味料4つ。

**チャーハン**
> 残りご飯と卵があれば、今夜はもう決まり。
> 強火で2分、鍋を振れなくても混ぜれば足りる。

**鮭の塩焼き**
> 朝ごはんの匂いの代表格を、自分の台所で。
> 塩を振ってグリルで8分、それだけ。

## 反例（これは書いてはいけない）

**豚の角煮（悪い例）**
> とろとろ食感がたまらない絶品おかず。
> ご飯が止まらない人気メニューです。

失格理由: 宣伝語のみで皿の固有情報がゼロ。皿名を差し替えても成立してしまう。この「どの皿にも貼れる」文が最大の失敗。

**工程数だけを言い換えた悪い例**
> 鶏もも肉を焼く香りで、平日の夕食が整う。
> 4工程なら、しょうがの味を順に重ねられる。

失格理由: 「4工程なら」を別の数字に替えるだけで他の皿にも流用でき、実際の着手を助ける情報になっていない。

## 注意

- 模範例に出ている肉じゃが・チャーハン・鮭の塩焼きも、17皿の中に含まれます。模範例と全く同じ文をそのまま使ってよいですが、それ以外の14皿は自分で書くこと。
- 完了したら `data/phase-b/intros-batch-0.json` を書き出して終了。他のファイルは一切変更しない。質問があれば止まらず、保守的な判断で進める。
