# 近さスコア パイロット（25皿）— 2026-07-16

ADR-009の特徴量スキーマとU1デフォルト重みを、282皿量産の前に25皿で検証した結果。

## スキーマ（Dish v4 パイロット版）

| tier | S / A / B |

| methods | 調理法（炒める/煮る/焼く/揚げる/蒸す/和える/茹でる/漬ける） |

## 検証結果: うまく動いた箇所

- **唐揚げ ↔ 竜田揚げ 0.83** / **ぶり照り ↔ 鮭照り 0.70** / **親子丼 ↔ カツ丼 0.78** / **豚汁 ↔ けんちん汁 0.71** / **ハンバーグ ↔ 煮込みハンバーグ 0.73** — 際どい同族ペアが全部最上位に来た
- **生姜焼き → 鮭照り・ぶり照り 0.60（1・2位）** — 甘辛だれ軸のクロス箱ブリッジが最重要ケースで機能。「肉の照り文法から魚へ」が調味料重み経由で自然に出る
- **とんかつ ↔ あじフライ 0.92** — パン粉衣軸で肉→魚の揚げ物ブリッジも成立
- **麻婆豆腐 → キーマカレー 0.58** — ひき肉+にんにく生姜+炒め煮。意外だが筋は通っている

## 検証結果: 見つかった問題（量産前に直す）

1. **調理法+工程のベースライン汚染**。「煮る+炒める」皿同士は調味料ゼロでも0.30が無条件に付く（例: カレーライス→豚汁 0.41、調味料0.00）。調理法語彙が粗すぎる（煮込む/さっと煮/汁物が全部「煮る」）。対処案: W_METH 0.20→0.15、W_STEPS 0.10→0.05 に下げ、調理法語彙を1段細分化。
2. **調味料が1〜2個の皿はどこへ行っても低スコア**（鮭の塩焼き{塩}、焼きそば{ソース}）。小さい集合のDiceは不安定。対処案: 語彙設計時に確認、必要なら overlap係数とのブレンド。
3. **同族0.8帯とブリッジ0.6帯が連続体**で、スコア単体では「双子」と「橋」を区別できない。推薦で双子ばかり出すと多様性が死ぬ。対処案: 後段ルール（食材Dice=1.0 かつ 調理法Dice=1.0 → variant扱いで推薦間引き）。地図は無処理でよい。
4. **さばの味噌煮の隣が親子丼0.48**になったのは、パイロット25皿に煮魚ファミリー（かれい煮付け・金目鯛・いわし梅煮）が居ないため。282皿では自然解消する見込み — スライス構成の問題でスコアの欠陥ではない。
5. **別名テーブルは前提条件として実証された**。カレールー/カレー粉の畳み込みが無いとカレー↔キーマが0.63→大幅低下する。282皿量産では調味料の統制語彙（30〜50語）と食材マスタを先に固めること（spec-030の前提条件昇格と一致）。

# v2（修正版）

再現: `scripts/proximity_pilot.py`（v2に更新済み）。修正内容:

1. **IDF重み** — カタログ内出現頻度の逆数で票を加重。豆板醤の一致は強い証拠、醤油の一致はほぼノイズ
2. **食材の役割タグ**（main/sub/coat/bind/thicken/base） — 同役割同士のみ一致。とんかつの卵パン粉（衣）とハンバーグの卵パン粉（つなぎ）は不一致に
3. **プール分割** — 副菜・汁ものは自プール内でのみ近さ順位。主菜との関係は相性軸（別機構、spec-030既定）。主菜↔ごはん麺クロスは×0.75減衰
4. **派生エッジの分離** — カツ丼⊃とんかつ は「似てる」でなく「部品として含む」。近さと別チャネル（derived_from）に
5. 調理法語彙の細分化（煮る/煮込む/さっと煮る/汁に仕立てる）+ 重み改定 0.45/0.30/0.15/0.05
6. **財布度（cost 1〜3）をスキーマに追加** — 近さスコアには不使用。週セット予算レンズ・reasonチップ・紹介文の代替表記（「牛こまで十分」）が消費者
