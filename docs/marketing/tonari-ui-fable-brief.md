# となりごはん「UI」壁打ちブリーフ — Fable向け

claude.ai/designで5画面を生成した。ゼロから作り直すのではなく、**この生成物（`~/Downloads/となりごはん.html`）を下地として使い、具体的な問題点だけを修正する**方針。正本はspec-030（体験設計）+spec-031（画面インベントリ）。

## 気に入らない点（オーナー記入・2026-07-04）

オーナーの言葉:
1. **背景色がAIっぽい** — クリーム/ベージュの淡色背景そのものが「AIが作るUIの平均」に見える
2. **コントラストが無さすぎて、見るべきものが見れない** — どこを見ればいいか視線が定まらない

生成物（`~/Downloads/となりごはん.html`, claude.ai/design出力）をHTMLレベルで検査した実データによる裏付け:

- **全サーフェスが同一の明度帯（ベージュ）に密集している**: 背景 `#E9DFCC`/`#F6EEDD`、カード `#FBF6EC`、タグ `#D2C4AB`（文字 `#8A7E70`）、補助テキスト `#8A7E70` on クリーム。背景・カード・タグ・本文がほぼ同じ「温度」で、面の分離が起きていない。オーナーの「見るべきものが見れない」の正体はこれ = **明度コントラストの階層が存在しない**
- **アクセント `#E8702A`（オレンジ）が万能キー化**している: 選択中タブ・主要CTA・タグ・ブランド名の全部に同じオレンジ。GPTレポートの指摘（色の役割潰れ→テンプレ感）と完全一致
- 難易度色（緑 `#8FA84E` / 橙系）は入っているが、上記2点に埋もれて効いていない

**つまり修正の本質は「色味を変える」ことではなく、(a) 面ごとに明度差=color roleを与えて視線の主従を作ること、(b) オレンジをCTA1用途に絞ること**。GPTのdeep researchレポート（`~/Downloads/deep-research-report (2).md`、下記に要点統合）も外側から同じ結論に到達している — AI臭の主因は主語の競合と情報階層の弱さで、装飾の問題ではない。

### GPTレポートの中核（Fableへの必読ポイント）

- **AI臭 = 同質化 + 情報階層の弱さ + コントロールの意味の混線 + 見た目偏重**（学術用語ではないが実務shorthandとして有効）
- 最優先で直すのは料理イラストより先に**「画面の主語」と「色の役割」**
- ホームの問題は「情報が多い」ではなく**「何がトップレベルで何が従属かの差が足りない」**。主語を「起点料理から一歩広げる」に固定し、難易度はその従属フィルタ（segmented control）に格下げ
- メイン推薦カードは**単一主題**に。3層構成（上=料理名+推薦理由 / 中=ビジュアル / 下=「前回との近さ」+「新しく増えるもの」）
- **メインはカード、サブはリスト**で階層差を出す（同じ密度で並べない）
- 色は最低4役割に分割: 焼き色オレンジ=CTA+選択中タブ / 緑=新食材・広がり / 茶=起点料理・履歴 / 淡い紙色=背景・カード
- 推奨パレット（レポート第一候補「紙のレシピ帳+焼き色」）: 背景 `#F4EBDD` / カード `#FFF9F2` / メインアクセント `#A75428` / サブ `#5E7A3A` / 本文 `#332821` / 補助 `#6B5A4B` / 罫線 `#E3D4C7` / タグ `#EEE0D2` / 危険 `#B4433A` / 成功 `#4F7A42`。※今のオレンジより一段くすませて生活感を出す方向
- 参考にすべきは「見た目が似てるアプリ」ではなく「主語が明確なアプリ」: DELISH KITCHEN（毎日の献立自動提案）/ Cookpad（自分のレシピ資産）/ Crouton（何を入れないか）/ Gentler Streak（今日できる次の一歩＝となりごはんに思想が最も近い）
- となりごはんが取るべき主語: **「前に作った料理から、今日できる一歩」**

全文は `~/Downloads/deep-research-report (2).md`。Fableに渡すときはこのmdも一緒に。

## そもそも何を作っているか

となりごはんは「レシピを検索するアプリ」ではなく「作れる料理を資産として育てる料理帳アプリ」。差別化軸はクラシル/クックパッドのような検索アプリの対極 — 検索アプリの体験は消費（毎回ゼロから探す）、うちは蓄積（使うほど資産が貯まる）。**UIも「検索アプリの見た目」に一切寄せてはいけない**。目指すのは「自分だけの、勝手に育つ料理帳」という個人の所有物の質感。

二本柱: レパートリー拡大の**コスト削減**（ホーム・探す）× **モチベーション増加**（料理帳・マップ）。画面ごとにどちらの感情を担うかが違うので、全画面を同じテンションでデザインしない。

## 画面と必須要素（spec-030/031より抜粋）

5画面固定（claude.ai/designの1回上限と同じ構成）:

1. **オンボーディング**（最重要・「配る瞬間」）: よく作る料理をチップ選択（12〜16品）。選ぶ楽しさが最優先
2. **ホーム**: 難易度タブ3つ+起点表示（「この前作った『〇〇』から広げる」）+メイン1件+小カード3件。工程数・調理時間は出さない
3. **探すタブ**: 料理名検索+食材チップ。対象は自分のレパートリーのみ
4. **料理帳（リスト）**: 先頭に成長サマリ1行+ランクバッジ3段階（作った/定番/十八番）
5. **料理詳細カード**: YouTube埋め込み(主役)+AIレシピ(「下書き」ラベルで控えめ)+URL添付(マイレシピピン)+あと一品(副菜2〜3)+作ったボタン

料理イラストは別トラック（後述）で様式未確定 — UIモック上は色面+器のシルエット程度の抽象プレースホルダーで扱う。

## AI臭チェックリスト（`.claude/rules/writing-style.md`より）

生成物が以下に2つ以上該当したら作り直し:
- 等サイズグリッドの反復（カード・アイコンが全部同じ大きさで並ぶ）
- バッジ/ピルの多用（差分がない装飾的なバッジの乱立）
- 汎用的な角丸カードの単調な繰り返し
- 中央揃え一辺倒のレイアウト
- ヒーロー/1枚目を見て1秒で「何のアプリか」が伝わらない

## claude.ai/design運用の既知の落とし穴（`reference-claude-design`メモリより）

- 1回のプロジェクトで5画面が上限（6画面目は自動生成されない）
- 色は「暖色系」のような曖昧語だとブレる。Hex指定必須
- グラフ/インタラクション状態（押下中等）は明示しないと出ない
- 追加メモ欄に書ける情報量が生成品質を左右する（今回の壁打ちで何が足りなかったかも上の記入欄に含めると次の手が立てやすい）

## 料理イラストの状況（UIモック上の扱いに影響）

粒状食材（ひき肉等）のイラスト様式はまだ確定していない（round4でGPT系4仮説を検証、Geminiに移行検討中）。**UIの見た目自体はイラスト様式に依存しない設計にしておきたい** — 抽象プレースホルダーで成立する強さを保つ。

## 料理帳セッションで出た関連知見（一貫性の参考）

別途「料理帳」の構造をFableに壁打ちさせたセッションで、UIレベルの具体提案も出た。今回のトーン設計と矛盾しないよう参考にしてほしい:

- **ランク（十八番/定番/作った）はバッジで示さず、文字の太さ・大きさ・色の濃さだけで示す**方向を提案していた（バッジ/ピル乱用のAI臭を回避する具体策）
- **セクションごとにわざと密度・サイズを変える**（十八番は大きく疎に、作ったは小さく密に）ことで等サイズグリッドの反復を構造的に回避
- 「そろそろ」のような状態変化は、新しい装飾要素を足すのではなく**既存要素の色味を半段だけ振る**程度に留める

これらは「装飾を足して差別化する」のではなく「装飾を削って構造で差をつける」方向性で一貫している。今回のUI回答もこの方向性で。

## Fableへの依頼形式（重要: ゼロからの再設計ではない）

**`~/Downloads/となりごはん.html` を直接開いて、その構造・画面構成・文言はそのまま活かした上で、色とコントラストの問題だけをパッチする**依頼にすること。5画面の構成・レイアウト・要素配置は既に良い（オーナーの不満は色にしか言及していない）。ゼロから代替案を何パターンも出させるのではなく、**既存HTMLに対する具体的な修正diff**（どのセレクタ/どの要素の色をどう変えるか）を求める。
