# となりごはん「料理帳」創造ブリーフ — Fable向け

> **最重要の前提**: 以下の「壁打ちで出た案」は**決定ではない。数ある案の一つ**にすぎない。データの土台（後述の確定制約）だけは守ってほしいが、料理帳をどう設計するかは白紙で考えてよい。この案を否定して別の構造を出してくれてもいい。むしろそれを期待している。

## そもそも何のための画面か

となりごはんは「レシピを検索するアプリ」ではなく「作れる料理を資産として育てる料理帳アプリ」。検索アプリの体験は消費（毎回ゼロから探す）、うちは蓄積（使うほど資産が貯まる）。

料理帳の正体は、壁打ちで**「習熟を助ける反復装置」**という捉え方に至った。核にあるオーナーの言葉: **「料理は何回も作らないと自分のものにならない。だからこれはそれを手助けるもの」**。つまり観賞用のトロフィー棚ではなく、脆い料理（一回だけ作った）を強い料理（十八番）に育てるのを助ける道具。

- 持たせる機能は2つ: ①作った料理が**勝手に記録される**（推測通知でワンタップ確定、入力労働ゼロ）②**作れる料理の把握**（今の自分の武器が一目でわかる）
- この2機能が「自分のものにする＝習熟」という一目的に串刺しになっている

## 確定している制約（変更不可）

- **3タブ固定**: 探す / ホーム / 料理帳。**4つ目のタブは作らない**
- **地図は料理帳タブの中の1ページ**（別ブリーフ `tonari-map-fable-brief.md` で地図の見た目は別途検討中）
- **ランク3段**: 作った → 定番 → 十八番（回数で自動昇格）
- **昇格の狙いは中間層の押し上げ**: 「作った」を「定番」へ、「定番」を「十八番」へ。十八番はもう自分のものなので放置（たまに維持する程度）
- **データ土台はADR-009（近さスコア）**: 料理は特徴量で定義、近さは無向スコアで自動計算。料理帳が描くのは全カタログではなく自分のレパートリー＋フロンティア
- **実行時AIは最小**（キャプチャ以外はヒューリスティクス/テンプレ）。買い切り前提のため

## 壁打ちで出た案（＝叩き台。決定ではない）

1. **習熟エンジンは完全に裏（silent）**。各料理に「脆さゲージ」や「あと1回で定番」の進捗を**表示しない**。アプリは内部で「脆さ×最後に作ってからの日数」を計算するが、画面には出さない
2. **再訪（もう一回作らせる）はホームのおすすめに溶かす**。専用のリマインダー基盤をv1では作らない。ホームの主語は「今日の一皿」ひとつのまま、その一皿が新しい料理（広げる）だったり脆い再訪皿（深める）だったりする。表には一行の理由（「新しく広げる」/「そろそろもう一回」）だけ。**再訪を独立セクションにしない**（主語の競合を避けるため）
3. **「そろそろ」印**は任意の軽いマーカー程度（あってもいい）。見せ方（ホームのカード上か料理帳のリスト上か両方か）は未決
4. **料理帳のデフォルト画面**は軽いランク順リスト＋「作れる料理N品」の一行サマリ。地図と振り返り/統計は料理帳内の**二階層目**（progressive disclosure）
5. **通知でアプリを開かせる話はv1では最小**。設計として「器はユーザー設定（時間帯・頻度・対象ランク）／中身はアプリが選ぶ／デフォルト優しく」だけ持っておいて、実装は後回し可

## この案を支えたリサーチ根拠

- **Duolingoは可視の「強度バー（錆びるゲージ）」を廃止した**。今は減衰を裏で静かに計算し、記憶が約50%に落ちた項目だけそっと再出題。可視ゲージは不安と視覚ノイズで逆効果だった → 「習熟エンジンは隠す」の根拠
- **優先順位は half-life 型**: 記憶が約50%に落ちかけた「縁にいる」項目を最優先（完全に忘れたものでも、まだ強いものでもない）。同点は「作った回数＞自分の評価＞最後に作ってからの日数」
- **通知はハイブリッドが倫理と実効の両立点**: ユーザーが器（時間帯・頻度・対象）を決め、アプリが中身（今日どの皿）を選ぶ。デフォルト週1・優しく・「1週間休む」逃げ道つき・全通知がユーザーの目的に奉仕する限りダークパターンにならない
- **progressive disclosure の実例**: 日常の軽い一覧と、たまに味わう統計/振り返りを分ける。Oura（Today/My Health）、Apple Fitness（Summary/Trends）、Letterboxd（diary/year-in-review）。ただし**となりごはんはタブを増やせない**ので、タブ分割ではなく料理帳タブ内の階層で実現する必要がある
- 蓄積が「自分の形」に見える仕掛け: Letterboxd（月ごとの密度差が成長の物語）、Strava（全履歴のヒートマップ）。**本のページめくり遷移はモバイルでは認知負荷が高く逆効果**（NN/g scrolljacking、Apple も iBooks の page-curl を廃止）なので不採用済み

## Fableに考えてほしいこと（自由記述・この案に縛られなくてよい）

- そもそも「習熟を助ける反復装置」という料理帳の捉え方自体、これがベストか。別の芯があるか
- silent（習熟を一切見せない）だと**成長の手応えが弱い**という懸念がある。認知負荷を上げずに「育ってる感」を出す視覚手段は何か。Letterboxd/Strava的な蓄積の可視化を、ゲージの押し付けにせずどう料理帳に落とすか
- 料理帳タブ内の階層UI（デフォルト＝作れる料理のリスト／地図／振り返り・統計）を、4タブに逃げずどう成立させるか。トグル？右上アイコン？別の発想？
- 「そろそろ」印の見せ方（出すとして、どこに、どんな強さで）
- 「作れる料理の把握」を、単なる長いリストにせず「これが自分の武器だ」という所有感・自信につなげる見せ方
