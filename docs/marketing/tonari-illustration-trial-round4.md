## 失敗の再診断（round3実物比較、2026-07-04）

`mocks/concept/gpt2/home-mid.png` を直接見て診断した。**同一画像内に成功例と失敗例が両方ある**:

- **失敗**: ガパオのひき肉+インゲンが、個々の粒を1粒ずつ描いた塊（カリフラワー/サンゴのような凹凸の集合）になっている。これが「気持ち悪い」の正体
- **成功**: 肉じゃがの牛肉は、個々の繊維を描かず**筆致1本＝肉片1つのリボン状の色面**で表現されている。粒を描いていないから成立している

結論: 絵本調そのものが悪いのではなく、**ひき肉・きざみ野菜を個別の粒として描写したことが原因**。肉じゃがの牛肉と同じ「色面+輪郭線数本」のルールを、ひき肉系にも適用すればよい。

補強情報（Web検索、2026-07-04）: 日本語の「ゆるい食べ物イラスト」解説では「正確に描くことより自由に描くことが大切。線の揺らぎや色のずれがそのまま味になる」（[atam-academy.com](https://atam-academy.com/blog/45922/)）という原則がある。精密な粒の再現を狙わないスタイルの方が土台として合っている。専用のひき肉描画チュートリアルは検索でも見つからず（ニッチすぎる）、根拠は上記の実物比較を主とする。

## 新プロンプトルール（全皿共通・既存スタイルガイドに追加）

既存の絵本調スタイルガイド（構図・色調等）は維持し、以下を**明示的に追加**する:

```
ひき肉・きざみ野菜・そぼろ状の食材は、個々の粒や繊維を1つずつ描かないこと。
代わりに、2〜4色の色面を大きな筆致でまとめて置き、ハイライトを2〜3箇所だけ
入れて質感を示す（肉じゃがの牛肉のような表現）。粒状のテクスチャ・点描・
凹凸パターンは禁止。
```

## 2026-07-04 セッション結論: GPT系(Codex image_gen)は一時停止、Geminiに切替

A/B/C/Dの4仮説を実施（下記）。**Dが最も有望**（かすれ技法=個別の粒を輪郭線で囲まず、
筆致の粗さだけで質感を出す。ビーズ状ハイライトも個別塊も出ず、ひき肉らしさも保持）。

ただし**オーナー判定でGPT系（Codex `image_gen.imagegen`、gpt-image系）より
Geminiの生成の方が料理表現で筋が良いという感触**が出たため、このラウンドはここで
一時停止。**次回はGeminiで同じ診断軸（個別の粒を輪郭線で囲まない/ビーズ状ハイライトを
避ける/ひき肉らしさを保持）を使って「調教」（プロンプト反復）をやり直す**。

GPT系での学び（Geminiでも流用できる診断軸）:
- ネガティブ指示（〜を描くな）だけでは粒の個別輪郭化という既定挙動を上書きしにくい
- 様式をフラットに振り切ると輪郭は消えるが「イラストすぎる」「塊がはっきりしすぎ」という
  別の不気味さが残ることがある
- 境界を溶かす指示は行き過ぎるとひき肉の食材性自体が失われ、ソース状になる
- 「かすれ」「掠れ筆」のような実在する技法名を指定すると、個別性を消しつつ質感を残す
  中間点に近づけた（D）。技法名の指定が有効な可能性が高く、Geminiでも試す価値がある
- 判定皿は引き続きガパオ（粒状食材の基準）

## 撤退ルールの数え方（2026-07-04改訂）

旧ルール「2回修正してもNGなら撤退」は曖昧だった（A/B/Cのような様式仮説の書き換えを1回の「修正」と数えるか不明確）。改訂:

- **round4は独立した予算を持つ探索フェーズ**とする（round3の全滅を受けた仮説転換のため）。「1回」= 1つの独立した技法・言語化仮説を実画像で検証すること
- **round4の予算: 最大5仮説**まで試す。A（同スタイル+粒禁止指示）/B（フラットベクター）/Cv1（境界を溶かす指示）で3消費済み
- 実物結果（2026-07-04）: A=まだ個別の塊+ビーズ状ハイライトが残り不気味 / B=フラットで光沢は消えたが「イラストすぎる」+塊の輪郭が気になる / Cv1=境界を溶かしすぎてカレーのソースのようになり、ひき肉らしさが消失。**3つとも「個別に描く」⇄「均質に溶かす」の両極端で、中間（粒感は残すが1個ずつ輪郭線で囲まない）が撃ち抜けていない**
- 残り予算2仮説。次点候補: 技法名を指定して中間を狙う（例: 乾いた筆でかすれさせる描法/岩絵具のたらしこみ等、実在する技法名を参照に使う）
- **5仮説を使い切ってもガパオがNGなら撤退線発動**（記録側=写真ゼロ完成デザイン、欲望喚起側=紹介文の五感語に全振り）
